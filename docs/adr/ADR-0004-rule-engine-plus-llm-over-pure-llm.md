# ADR-0004: 规则引擎 + LLM 混合，而非纯 LLM

> **状态：** 已采纳
> **日期：** 2026-07-11
> **决策者：** 陈家智（AI Architect）

---

## 背景

所有 Agent 的逻辑是全部用 LLM（Qwen2.5-7B）推理，还是部分用硬编码规则？

## 决策

**采用"规则引擎（硬编码）+ LLM（模糊推理）"混合架构，不采用纯 LLM 方案。**

## 理由

1. **硬约束不能交给 LLM：**
   - 五行→五音的映射（木=角/火=徵/土=宫/金=商/水=羽）是《黄帝内经》的确定知识，不是概率问题
   - LLM 可能"幻觉"出错误的映射关系（如"肝属火"）
   - 规则引擎保证核心知识 100% 准确

2. **LLM 适合模糊推理：**
   - "焦虑 82 分 + 抑郁 35 分 + 睡眠 40 分 → 什么证型？"——这是需要综合判断的模糊推理
   - 用户自由文本的情绪分析——LLM 比正则表达式强

3. **成本与延迟：**
   - 规则引擎：< 1ms，免费
   - LLM 推理：200-2000ms，有 GPU 成本
   - 核心路径走规则，只有边缘情况调 LLM

4. **可审计性：**
   - 规则引擎输出：100% 可复现，100% 可审计
   - LLM 输出：每次可能不同，难以审计
   - 比赛答辩时可以说"核心映射使用规则引擎确保医学准确性"

## 分工

| 环节 | 用什么 | 为什么 |
|------|--------|--------|
| 五行→五音映射 | **规则引擎**（硬编码） | 确定知识，不交给 LLM |
| 生克选调（木克土→加宫调） | **规则引擎**（硬编码） | 中医固定公式 |
| BPM 范围选择 | **规则表**（查表） | 可以做成配置表 |
| 证型综合判断 | **LLM**（Qwen2.5-7B） | 需要模糊推理 |
| 自由文本情绪分析 | **LLM**（Qwen2.5-7B） | NLP 任务 |
| 推荐理由生成 | **LLM**（Qwen2.5-7B） | 自然语言生成 |
| 西医→中医术语映射 | **规则引擎**（预设映射表）+ **LLM**（兜底） | 常见术语覆盖 80%，LLM 兜底 20% |

## 后果

- **正面：** 核心路径 100% 可预测、可审计。LLM 只用在真正需要模糊推理的地方。
- **正面：** 成本低（大部分推理不调 LLM）。
- **负面：** 规则表和映射表需要维护（nob 的工作量）。
- **负面：** 规则引擎 + LLM 两套逻辑，代码复杂度略高。
