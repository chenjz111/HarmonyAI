# HarmonyAI Sprint 3 比赛演示脚本

> 主讲：陈家智
> 目标：用一条可理解、可解释、可降级的完整链路展示 HarmonyAI
> 状态：演示脚本已准备；最终页面和接口需在队友 PR 合入后复测

## 1. 演示前准备

- 使用固定、虚构且不含真实隐私的案例；
- 后端、前端、本地音频均提前启动；
- 在线模式准备 Qwen，但不把网络成功作为唯一演示路径；
- 准备关闭 Qwen 的离线问卷模式；
- 准备一段完整录屏；
- 浏览器只保留演示页面、Swagger 和必要终端；
- 不在屏幕上展示 API Key、`.env`、患者真实材料或绝对文件路径。

## 2. 开场

> 大家好，我是项目负责人陈家智。HarmonyAI 不是让用户先选一个情绪、再随机播放一首音乐的普通音乐 App。它是一套通过多源表达理解用户状态、完成中医辅助辨证，并形成个性化音乐调养方案的多智能体系统。
>
> Sprint 2 解决的是“五个 Agent 能否连起来运行”；Sprint 3 解决的是“用户能否真正使用、评委能否看懂、外部 AI 失败时系统能否继续运行”。

## 3. 固定案例

用户输入：

> 最近要考试了，我明明复习了，但晚上还是一直想自己会不会考不好。躺下之后脑子停不下来，最近胃口也不太好，白天没精神。我不知道自己算不算焦虑，就是感觉很累。

可选材料：

> 一张虚构的睡眠相关门诊记录图片。OCR 识别结果必须先由用户确认。

问卷预期：

- 紧张担忧：中等偏高；
- 思虑过多：较高；
- 睡眠：入睡困难；
- 精力：偏低；
- 食欲：轻度变化；
- 日常影响：中等。

## 4. 页面演示

### 4.1 欢迎页

操作：点击“开始今日状态评估”。

讲解：

> Sprint 3 不再要求用户一进来就判断自己属于喜、怒、思、悲、恐。用户可能并不知道自己的准确情绪，所以我们先让他表达，再由 AI 理解，最后由用户确认。

### 4.2 病例材料页

操作：上传虚构材料，或展示“跳过”。

讲解：

> 材料不是用来让 AI 看病，而是提取用户已有医疗材料中的症状和医生描述，作为音乐调养的辅助背景。OCR 文本必须先让用户确认；识别失败时可以跳过，不会阻断流程。

### 4.3 自由描述页

操作：粘贴固定案例。

讲解：

> 用户不需要组织专业语言，可以直接写最近发生的事情、压力、睡眠和身体感受。Assessment Agent 会把自然语言转换为结构化状态信息。

### 4.4 图文问卷页

操作：完成 12 题。

讲解：

> 问卷控制在 3 分钟内。天气、海面、电池等图形题降低表达门槛，但它们不会单独决定中医证型或音乐调式。核心题仍采用统一的 0—4 频率量表。

### 4.5 评估结果页

预期展示：

- 主要状态：焦虑、思虑较多；
- 诱因：考试压力和自我怀疑；
- 身体表现：睡眠差、食欲下降、疲惫；
- 中医情志倾向：思为主，恐为辅；
- 输入来源：材料、自由描述、问卷；
- 非诊断声明。

讲解：

> 这里展示的不是一句“你很焦虑”，而是状态、诱因、身体表现、证据来源和限制。系统置信指标反映的是输入是否充分、格式是否合法、来源是否一致和执行路径是否可靠，它不是疾病概率，也不是医学准确率。

### 4.6 用户确认

用户补充：

> 我不是特别害怕，主要是脑子停不下来。

讲解：

> 系统采用“AI 初评—用户确认—动态修正”。这样可以避免把大模型的一次输出直接当作最终结论。

### 4.7 辨证与音乐处方

预期展示：

- 辅助辨证倾向：心脾两虚倾向；
- 调式：宫调；
- BPM：58；
- 乐器：古琴、洞箫；
- 时长：15 分钟；
- 推荐依据；
- `source_type=matched`。

讲解：

> Diagnosis Agent 给出辅助辨证倾向，Prescription Agent 再把它转换成可以执行的音乐参数。当前比赛版使用本地曲库匹配，页面会明确标记 matched，不会把本地音乐包装成 AI 实时生成。

### 4.8 播放与 Feedback 2.0

操作：

- 播放本地音乐；
- 填写听前和听后状态；
- 选择放松程度、匹配度、是否收藏；
- 标记“不喜欢高频笛声”；
- 主动提交反馈。

讲解：

> Feedback Agent 不只是收集星级。它会形成个人偏好补丁，例如下次降低节奏、减少高频笛声、保留古琴。它不能自动修改全局医学规则，也不能用五星评价证明辨证正确。

## 5. 五 Agent 一句话说明

1. Assessment：把材料、自由描述和问卷整理成结构化状态画像；
2. Diagnosis：根据状态画像和审核规则给出辅助辨证倾向；
3. Prescription：把辨证倾向转换为调式、BPM、乐器和时长；
4. Music：按照处方匹配可播放的本地音乐；
5. Feedback：比较听前听后状态，更新个人音乐偏好。

## 6. 降级演示

### 6.1 OCR 失败

> OCR 失败时，页面提示用户重新上传、手动补充或跳过。系统将材料状态标记为 degraded，继续自由描述和问卷。

### 6.2 Qwen 失败

> Qwen 未配置、超时或输出 JSON 不合法时，系统重试一次，然后自动切换到确定性问卷和本地规则路径。页面会如实显示“基础问卷评估”，不会伪造 AI 成功。

### 6.3 两者同时失败

> 即使 OCR 和 Qwen 同时失败，用户仍可以只完成问卷，得到基础状态评估、本地规则处方和曲库音乐。这就是系统的工程可靠性。

## 7. 常见评委问题

### “五个 Agent 都是大模型吗？”

> 不是。需要自然语言理解的 Assessment 优先调用 Qwen；确定性问卷、安全规则、中医映射和曲库匹配更适合使用规则与知识库。成熟的多智能体系统不是每一步都调用大模型，而是让不同能力各司其职。

### “可信度是怎么来的？”

> 它是工程置信指标，由输入来源覆盖、Schema 合法性、来源一致性和执行可靠性组成。它不是医学诊断准确率，也不是模型自报分数。外部服务降级、信息冲突或输入缺失都会降低该指标。

### “上传病例是不是 AI 看病？”

> 不是。系统只提取用户已有材料中的辅助背景，并要求用户确认，不修改医生诊断、不建议停药换药，也不代替医生。

### “音乐是实时生成的吗？”

> 当前比赛版是参数化本地曲库匹配，返回 `source_type=matched`。真实音乐生成是未来可插拔能力，本次没有伪装成已完成。

### “用户反馈会不会把医学规则带偏？”

> 不会。反馈只更新个人层面的乐器、节奏、时长和环境音偏好。全局医学知识只能经过人工审核、测试和版本化发布。

## 8. 结束语

> HarmonyAI 的核心不是给情绪贴标签，也不是随机推荐音乐，而是把“用户表达—AI 理解—用户确认—辅助辨证—音乐处方—播放反馈—下次优化”做成一条可解释、可追踪、可降级的多智能体闭环。
