## 1. Sprint 目标

Sprint 3 的目标是在保护 Sprint 2 五 Agent 闭环的基础上，完成比赛版体验重构与多源评估升级：

```text
病例材料（可跳过）
  + 自由描述（可跳过）
  + 12题图文问卷（稳定基线）
  → 状态评估
  → 可解释辅助辨证
  → 音乐参数处方
  → 本地曲库匹配与播放
  → 多维反馈
  → 个人偏好更新
```

## 2. Sprint 2 与 Sprint 3 的区别

| 维度 | Sprint 2 | Sprint 3 |
|---|---|---|
| 主要目标 | 验证五 Agent 能连通 | 形成评委可体验的比赛闭环 |
| 用户入口 | 先选情绪、再问卷 | 先表达，再由 AI 理解 |
| 输入 | 问卷 + 初步自由文本 | 材料、自由文本、图文问卷 |
| 结果 | Agent 输出和本地播放 | 来源可追踪、结果可解释、用户确认 |
| 音乐 | 本地 Generation stub | 结构化 Music Agent + `matched` 标记 |
| 反馈 | 星级和评论 | 听前听后、放松、匹配度、偏好 |
| 降级 | Qwen 本地规则 fallback | OCR、Qwen、知识库、音频和保存降级 |
| 安全 | 初步文本关键词 | 多来源确定性风险规则与安全阻断 |

## 8. 已知限制

- 当前音乐以本地曲库匹配为主，不是实时 AI 音乐生成；
- 病例材料只支持比赛限定格式和演示范围；
- 系统输出是状态评估与辅助辨证倾向，不构成医学诊断；
- 可信度是工程置信指标，尚未经过临床数据校准；
- Feedback 只影响个人音乐偏好，不自动学习全局医学规则；
- P1 的语音、多轮聊天、用户系统和七日疗程不在本次范围。
