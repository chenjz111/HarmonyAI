## 三、各角色详细职责

### 3.1 陈家智 —— Project Leader & AI Architect

**你的工作不是写代码，而是制定标准、推动项目。**

#### 三大架构设计（核心创新）

| 架构层 | 你做什么 | 别人做什么 |
|--------|----------|------------|
| **Knowledge Architecture** | 设计知识映射链：Emotion→Syndrome→Wuxing→Tone→Music Feature→Prompt Tag；定义JSON Standard | Medical Knowledge Engineer 按照你的标准填充文献和映射数据 |
| **Prompt Architecture** | 设计Prompt Framework：模板结构、参数体系、组装规则 | AI Engineering Lead 按照你的框架实现Prompt Engine |
| **Agent Architecture** | 设计Agent Development Standard：每个Agent的输入输出规范、状态转换、异常处理 | AI Engineering Lead + Backend 按照你的标准开发 |

#### 你负责制定、别人执行的

| 标准/规范 | 你制定 | 谁执行 |
|-----------|--------|--------|
| JSON Standard | 所有Agent的Schema结构、字段命名、版本号规则 | 全员遵循 |
| API Standard | 接口路径、请求/响应格式、错误码 | Backend 实现 |
| Git Standard | 分支命名、Commit格式、PR流程 | 全员遵循 |
| Sprint 制度 | 任务拆分、验收标准、Review流程 | 你主持，全员参与 |
| Review 制度 | 架构Review + 知识Review + 代码Review | 你Review架构和知识，Backend Review代码 |

#### 日常工作

| 时间 | 工作 |
|------|------|
| **上午** | Architecture Review——检查AI Engineering的LangGraph改动、Backend的API是否偏离Schema |
| **下午** | Medical Review——检查Medical Knowledge的文献是否按Knowledge Architecture标准标注 |
| **晚上** | Sprint Planning——根据当天进度，调整第二天任务分配 |

#### 具体职责清单

**项目管理（40%）**
- 与老师沟通、定期汇报
- Sprint规划与任务分配
- 所有Pull Request的架构级Review
- 风险识别与进度控制
- 参赛材料统筹

**AI系统架构（40%）**
- Knowledge Architecture 设计
- Prompt Architecture 设计
- Agent Architecture 设计
- JSON Standard / API Standard 制定
- 技术选型与架构决策

**产品路线（20%）**
- 用户需求分析
- 功能优先级排序
- 产品迭代路线

#### 不负责

- ❌ 查论文 / 录JSON / 填映射数据（Medical Knowledge Engineer 做）
- ❌ 写 LangGraph / Chroma / Qwen / Prompt Engine 代码（AI Engineering Lead 做）
- ❌ 写 FastAPI / MySQL / Redis / Docker（Backend Platform Engineer 做）
- ❌ 写 uni-app / UI / 动画（Client Engineer 做）

### 陈家智 —— 标准制定 + 项目基础设施

```
Day 1 上午
  ├── 主持 Kickoff Meeting（30分钟）
  ├── 创建 GitHub 仓库 + README + 目录结构
  ├── 建 GitHub Projects 看板（To Do / In Progress / Review / Done / Blocked）
  ├── 建 5 个 Milestone Issue（每人一个，附验收标准）
  └── 创建分支策略（main / dev + 每人一条 feature 分支）

Day 1 下午
  ├── 制定 Knowledge Architecture 标准——
  │   文档化完整的映射链：
  │   Emotion → Syndrome → Wuxing(Element/Organ) → Tone → Music Feature(BPM/Instruments/Ambient) → Prompt Tag
  │   每条映射标注：字段类型、必填/可选、示例值、来源文献要求
  └── 产出 docs/knowledge-architecture.md

Day 2 上午
  ├── 制定 Prompt Architecture 标准——
  │   定义 Prompt 模板结构（Template ID / Parameters / Assembly Rules）
  │   定义参数体系（调式/权重/BPM/乐器/环境音/情绪/场景/时长）
  │   定义模板版本号规范
  └── 产出 docs/prompt-architecture.md

Day 2 下午
  ├── 制定 Agent Architecture 标准——
  │   每个Agent的通用字段规范（agent_id / version / confidence / reason）
  │   输入输出Schema的版本管理规则
  │   异常处理与降级标准
  └── 检查全员进度 + 解决阻塞

Day 3 上午（Sprint Review）
  ├── 主持 Review
  ├── 演示3份 Architecture 标准文档
  ├── 演示 GitHub 仓库 + 看板
  └── 汇总问题 + 分配整改

Day 3 下午
  └── 修Review问题 + 晚上向老师汇报
```

**✅ 验收标准：** `knowledge-architecture.md` + `prompt-architecture.md` + GitHub仓库可访问 + 看板5个Issue

**❌ 不负责：** 不查文献、不填JSON、不写代码
