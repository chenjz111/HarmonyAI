> 日期：2026-07-11

## 一、目前我们对整个项目架构的理解

目前我们理解，整个系统可以采用**五个智能体协作**完成。

### Agent1：评估智能体（Evaluation Agent）

负责收集用户健康信息。主要有两种输入方式：

**① 医疗病例输入**

用户上传西医诊断或中医诊断。如果是西医诊断，利用大模型结合医学知识库，将西医专业术语转换为对应的中医辨证信息。同时结合《黄帝内经》《伤寒论》等中医文献，对情绪、睡眠、压力等指标进行量化。

例如：

- 焦虑症 → 肝郁化火、心神不宁
- 睡眠障碍 → 心肾不交

最后形成统一的用户健康画像：

```json
{
  "焦虑": 82,
  "睡眠": 40,
  "疲劳": 65,
  "压力": 78
}
```

**② 问卷标签输入**

对于没有病例的用户，可以采用健康问卷。例如：

- 是否失眠
- 是否容易烦躁
- 是否胸闷
- 是否怕冷
- 是否食欲下降

最终同样形成统一的数据结构。

---

### Agent2：中医辨证智能体

这一层负责真正完成中医辨证。

**输入：** 用户健康画像

**输出示例：**

- 肝郁化火
- 阴虚
- 心神不宁

**主要依赖：**

- 中医知识库
- 中医规则
- 大模型推理

---

### Agent3：音乐处方智能体

我们认为：**这一层实际上不是生成音乐，而是把中医辨证结果转换成音乐参数。**

```
肝
  ↓
木
  ↓
角音
  ↓
角调
  ↓
古琴
  ↓
竹笛
  ↓
60 BPM
  ↓
舒缓
  ↓
流水环境音
```

最后生成 AI 音乐模型可以理解的 Prompt。例如：

> 请生成8分钟中国民族风音乐，以角调式为核心，采用古琴、竹笛，速度60BPM，整体舒缓自然，适合睡前放松。

---

### Agent4：音乐生成智能体

调用国内音乐生成平台。

**输入：** Prompt

**输出：** 音乐

---

### Agent5：反馈智能体

负责用户试听与反馈收集：

- 满意度
- 是否改善睡眠
- 是否继续推荐
- 可穿戴设备数据（未来）

然后不断优化。

---

## 二、我们对于整个系统架构的进一步理解

我们觉得：**五个Agent负责的是功能分工。但是整个系统内部还可以划分三个逻辑层。**

```
┌─────────────────────────────────────────────────────────────┐
│                    第一层：医学分析层                        │
│                                                             │
│    用户信息 → 健康评估 → 中医辨证                           │
│                                                             │
│    输出：中医结果                                            │
│    （到此为止，完全不涉及音乐）                               │
├─────────────────────────────────────────────────────────────┤
│                    第二层：知识映射层 🔥                     │
│                   （我们认为最重要）                         │
│                                                             │
│    辨证结果 → 五行 → 五脏 → 五音 → 调式 → 乐器 →            │
│              节奏 → 环境音 → Prompt                        │
│                                                             │
│    这一层就是：中医知识到AI音乐参数之间的映射                │
│    我们认为这可能是整个项目最大的创新点                      │
├─────────────────────────────────────────────────────────────┤
│                    第三层：AI生成层                          │
│                                                             │
│    Prompt → AI音乐平台 → 生成音乐 → 反馈学习                │
│                                                             │
│    （到此为止，完全不涉及中医）                               │
└─────────────────────────────────────────────────────────────┘
```

### 五智能体与三层架构的叠加关系

| 五Agent（老师方案） | 三层架构归属 |
|---------------------|-------------|
| ① 评估Agent | 第一层：医学分析层 |
| ② 中医辨证Agent | 第一层：医学分析层 |
| ③ 音乐处方Agent | **第二层：知识映射层** 🔥 |
| ④ 音乐生成Agent | 第三层：AI生成层 |
| ⑤ 用户反馈Agent | 第三层：AI生成层 |

> 五Agent回答"谁来干活"，三层架构回答"数据怎么流动、知识怎么转换"。两者互补叠加，不冲突。

## 三、关于"七调映射五音"的理解

这是我们目前重点思考的问题。

目前查阅了一些关于五音疗法的研究，发现：

- 大部分文献都强调五音（宫、商、角、徵、羽）对应五行、五脏、五志
- 但是，**目前没有查到明确文献指出 AI 音乐必须完全禁止 Fa 和 Si**
- 反而有研究认为：五音疗法可以采用**五声调式、六声调式、七声调式**

因此，我们目前倾向于认为：

> **五音是中医理论基础。而现代AI生成音乐可以以五声音阶或五音调式为主体，必要时允许少量装饰音。**
>
> 重点应该放在：**如何把辨证结果转换成调式、乐器、节奏等音乐参数**，而不是简单删除 Fa 和 Si。

**主要文献依据：**

| 文献 | 来源 | 核心观点 |
|------|------|----------|
| 《五行音乐疗法及其择时应用探析》（2024） | 《山东中医杂志》 | 五音治疗体系由五声调式、六声调式与七声调式共同构成 |
| 《中医五行音乐疗法的研究进展》 | — | 治疗理论建立在五音上，学术界未形成"必须删除Fa/Si"的统一观点 |

---

## 四、目前想到的一个创新方向

相比直接"用户 → AI生成音乐"，我们希望**增加知识映射层**。

整个流程变成：

```
用户 → 评估 → 辨证 → 五行 → 五音 → 调式 → 乐器 → Prompt → AI音乐生成
```

这样，**AI 并不是直接生成**，而是**先经过中医知识映射，再生成音乐**。

我们认为：

> 项目真正的核心创新点，不只是"AI生成音乐"，而是建立一套 **"中医辨证 → 五行 → 五音 → 音乐参数 → AI Prompt"的知识映射机制**。
>
> AI负责生成音乐，而知识映射负责保证生成结果符合中医理论。

这样更符合中医理论，同时也体现 AI 智能体协作的设计思想。
