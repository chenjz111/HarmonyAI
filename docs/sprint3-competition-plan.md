# HarmonyAI Sprint 3 比赛版规划

> 主题：比赛版体验重构与多源评估升级  
> 计划周期：2026-07-28 至 2026-07-31  
> 文档性质：实施规划，不代表相关接口或页面已经完成

## 1. Sprint 目标

Sprint 3 不推翻 Sprint 2 已跑通的五 Agent 链路，而是在保持旧版可运行的前提下，将产品入口、评估方式、解释能力、音乐输出和反馈闭环升级为可参赛演示的版本。

本 Sprint 的最终目标是让评委在一次完整体验中清楚看到：

1. 用户不需要先判断自己属于哪一种情绪；
2. 系统可综合医生材料、自由描述和图文问卷；
3. Assessment Agent 输出结构化状态评估；
4. Diagnosis Agent 给出可解释的辅助辨证倾向；
5. Prescription Agent 将辨证倾向转换为音乐参数；
6. Music Agent 以结构化结果匹配并播放本地曲目；
7. Feedback Agent 根据听前、听后和音乐体验更新个人偏好；
8. OCR 或 Qwen 不可用时，主链路仍可依靠问卷完成。

对外统一定位：

> HarmonyAI 是一个通过多源表达理解用户状态、完成中医辅助辨证，并生成个性化音乐调养方案的多智能体系统。

所有用户端内容必须使用“状态评估”“辅助辨证倾向”“音乐调养建议”等表述，不能宣称医学诊断或治疗效果。

## 2. 当前状态基线

### 2.1 已经存在并应保护的能力

- uni-app + Vue 3 前端，现有页面为首页、情绪选择、问卷和播放器；
- FastAPI 后端，已有 `/api/v1/assessment`、`diagnosis`、`prescription`、`generation`、`feedback` 五类接口；
- LangGraph 五 Agent 顺序链路已可离线运行；
- Assessment Agent 已支持 `narrative_text`，配置 Qwen 后可进行结构化文本理解；
- Qwen 不可用时，Assessment 和 Diagnosis 已有本地规则降级；
- Prescription Agent 已能输出调式、BPM、时长、乐器、Prompt 和知识依据；
- Generation 当前使用本地音频，已有 `/static/music/jiao-demo.wav` 演示资源；
- Feedback 当前支持星级和选填评论，AI 引擎侧可写入 SQLite；
- 后端测试目录中现有 47 个测试函数，另有 1 个前端组件结构测试。

### 2.2 当前尚未存在的能力

- 图片或 PDF 上传接口、OCR 适配器和材料确认页面；
- 多源输入的统一数据结构与融合策略；
- 10—12 题图文问卷；
- 独立的分析中状态和可解释评估结果页面；
- 面向比赛展示的 Music Agent 结构化输出；
- Feedback 2.0 多维字段和完整个人偏好更新；
- v2 工作流编排接口与会话查询接口；
- 覆盖新流程的端到端测试。

### 2.3 测试基线说明

现有测试源码包含 47 个后端测试函数。当前项目 `.venv` 与桌面内置 Python 环境均未安装 `pytest`，因此本规划阶段未新增依赖、也未重跑测试。实施阶段必须先建立可重复测试环境，再以“原 47 项全部通过”为回归底线。

## 3. 现有设计与 Sprint 3 新需求的冲突

| 编号 | 现有设计 | Sprint 3 要求 | 处理原则 |
|---|---|---|---|
| C-01 | 首页先展示五音卡片，随后要求选择单一情绪 | 先询问材料，再自由描述和问卷 | 新增 v2 入口；旧页面保留作兼容或快速体验，不再作为主流程 |
| C-02 | 现有问卷共 30 题，使用 1—5“像我”量表 | 10—12 题、3 分钟内、核心题 0—4 频率量表 | 新建 Questionnaire V2，不直接修改旧答案语义 |
| C-03 | 自由描述已加入 `survey.vue`，但仍位于情绪选择之后 | 自由描述应位于病例材料之后、问卷之前 | 将自由描述拆为独立页面 |
| C-04 | 前端提交后直接进入播放器 | 必须展示分析中和可解释结果 | 新增结果状态页；用户确认后才继续处方 |
| C-05 | 当前反馈主要是星级，真实工作流还会默认写入 4 星 | 需要听前/听后、多维体验和用户主动提交 | 禁止自动生成反馈；只有用户操作后才能写入 |
| C-06 | 旧架构文档允许群体低满意度触发全局权重矩阵更新 | 反馈只能更新个人偏好 | Sprint 3 明确覆盖旧规则：全局医学规则只能人工审核、测试、版本化发布 |
| C-07 | 内部对象和路由使用 `diagnosis` | 用户端不能称医学诊断 | 后端旧命名为兼容保留，用户端统一显示“辅助辨证倾向” |
| C-08 | `evaluation_agent` 与 `assessment_agent` 两种 ID 并存 | 需要清晰的 Agent 展示 | v2 规范使用 `assessment_agent`，读取旧数据时接受 `evaluation_agent` 别名 |
| C-09 | `schemas/v1.0` 为空，部分路由直接接收 `dict` | 多源输入和反馈需要稳定契约 | v2 使用明确的 Pydantic/JSON Schema；v1 不破坏 |
| C-10 | 安全检测目前主要覆盖自由文本中的自伤词 | 还需覆盖严重胸痛、呼吸困难等风险 | 安全规则前置到所有来源，并阻断普通音乐建议链路 |
| C-11 | 生成接口目前始终返回本地音频 | P0 要求 Music Agent 结构化输出，但不做 SkyMusic | 明确标记 `generation_mode: matched`，不伪装实时生成 |
| C-12 | 新流程文字列出 9 个阶段，但要求文档描述 8 个页面 | 页面数量需一致 | 将“AI 分析中”作为“评估结果页”的加载状态，共 8 个路由页面 |

## 4. 范围

### 4.1 P0：本 Sprint 必须完成

1. 新欢迎入口，不再强制先选情绪；
2. 病例材料上传与跳过，支持 JPG、PNG、PDF 的比赛限定范围；
3. 独立自由描述页面，可跳过；
4. 12 题图文问卷，至少 3 题使用图形或图标卡片；
5. 病例确认文本、自由描述和问卷结果的多源融合；
6. AI 分析中状态与可解释状态评估结果；
7. 用户确认评估后再进入辅助辨证；
8. Music Agent 结构化输出及本地曲库匹配；
9. Feedback 2.0；
10. 全流程 UI 视觉升级；
11. OCR、Qwen、知识检索失败时的明确降级；
12. 三条端到端场景与旧版回归测试。

### 4.2 P1：有余量时完成

- 用户对评估标签进行逐项确认、删除和补充；
- 上传材料的手动 OCR 文本纠正；
- 多 Agent 执行进度和依据摘要展示；
- 收藏曲目后的“再次播放”入口；
- 一次会话详情页；
- 基础埋点：各页面耗时、跳过率、降级率；
- 第二首或第三首本地曲目，用于展示偏好调整；
- 统一视觉组件和无障碍字号适配。

### 4.3 Out of Scope

- SkyMusic 或其他真实音乐生成；
- 语音输入或语音情绪识别；
- 多轮聊天；
- 可穿戴设备接入；
- 七日疗程；
- 支付和会员；
- 完整注册登录与用户系统；
- 自动训练；
- 根据个人或群体反馈自动修改全局医学知识、证型规则或五音映射。

## 5. 新用户流程

```text
欢迎页
  → 病例上传页（上传 / 跳过）
  → 自由描述页（填写 / 跳过）
  → 图文问卷（必填）
  → 评估结果页（先显示 AI 分析中）
  → 可解释评估结果（同一页面成功态）
  → 音乐处方和播放器
  → 多维反馈
  → 完成页
```

三种输入的关系：

- 问卷是 P0 的稳定基线，必须完成；
- 自由描述用于补充事件、情绪和身体状态；
- 医生材料只能作为经用户确认的辅助背景；
- 任一可选来源失败或跳过，不能阻断问卷主链路；
- 严重风险信号优先于普通评估结果，必须展示安全提示。

## 6. 技术与产品原则

### 6.1 多源融合

- 每条结论都记录来源：`document`、`narrative` 或 `questionnaire`；
- 问卷分数由确定性计分产生，不允许 Qwen 随意改写；
- OCR 文本必须先展示给用户确认，未经确认不得作为可靠事实；
- Qwen 负责信息提取、归纳和冲突提示，不负责替代安全规则；
- 当来源冲突时，结果页展示“信息不一致，建议补充或以本人当前感受为准”。

### 6.2 可解释性

结果至少展示：

- 当前主要状态；
- 强度或频率；
- 可能诱因；
- 睡眠、精力、食欲等身体与生活表现；
- 关联的中医情志；
- 辅助辨证倾向；
- 支撑依据及来源；
- 缺失信息、冲突和降级说明；
- “不构成医学诊断”的固定提示。

### 6.3 安全边界

- 自伤、自杀表达：停止常规推荐，显示危机安全提示；
- 严重或持续胸痛、明显呼吸困难等急性危险信号：提示立即寻求急救或线下医疗帮助；
- 不给出疾病确诊、停药、换药或替代医生的建议；
- 上传文件默认只用于本次评估，比赛版不做长期原件存储；
- 日志不得记录原始病例全文、身份证号、手机号等敏感内容。

## 8. 风险与降级策略

| 风险 | 触发条件 | 用户可见处理 | 系统处理 |
|---|---|---|---|
| OCR 不可用 | 超时、服务异常、无法识别 | “材料暂未识别，可手动补充或跳过” | 标记 `ocr_status=degraded`，继续自由描述和问卷 |
| PDF 不受支持 | 加密、损坏、页数超限 | 提示重新上传图片或跳过 | 不进入 OCR，不保存不合规文件 |
| Qwen 不可用 | 未配置、超时、格式错误、重试失败 | “已切换到基础问卷评估” | 使用确定性问卷分数和本地规则 |
| Qwen 输出不合法 | JSON 不符合 Schema | 不展示原始输出 | 重试一次，仍失败则降级 |
| 三源信息冲突 | 材料、文本、问卷结论不一致 | 展示冲突摘要，请用户确认 | 不自动选择医学结论，降低可信度 |
| 知识检索失败 | Chroma 不可用或无命中 | 展示基础解释与降级标记 | 使用已审核本地规则 |
| 本地音乐缺失 | 路径错误或加载失败 | 提供重试与备用曲目 | 切换已验证的默认音频 |
| 反馈保存失败 | 数据库不可用 | 保留页面输入并允许重试 | 不伪造成功，不更新个人偏好 |
| 高风险内容 | 自伤、急性胸痛、呼吸困难 | 显示醒目安全提示 | 阻断普通音乐处方，记录非敏感风险代码 |
| 截止期过短 | P0 延迟 | 保证完整主链路，移除 P1 | 7 月 30 日晚冻结范围 |

## 9. Definition of Done

Sprint 3 只有同时满足以下条件才算完成：

### 功能

- 八个页面按顺序可访问，跳过逻辑正确；
- 图片/PDF 上传成功或失败后都能继续；
- 自由描述可填写、可跳过；
- 12 题问卷可在 3 分钟内完成，核心题使用 0—4；
- 评估结果标明使用了哪些输入来源；
- 用户能看到可解释依据、风险提示和非诊断声明；
- 用户确认后能得到结构化处方和可播放的本地音乐；
- Feedback 2.0 完整提交，并只产生个人偏好更新。

### 降级

- 关闭 Qwen 后，问卷模式仍可走到完成页；
- OCR 失败后，用户可手动补充或跳过；
- 自由描述为空不报错；
- 三个来源只保留问卷时仍能生成基础状态评估；
- 任何高风险信号不会被普通音乐建议覆盖。

### 质量

- 原 47 个后端测试全部通过；
- 新增 v2 单元、契约和端到端测试全部通过；
- 前端无阻断性控制台错误；
- 接口错误有统一错误码和可理解文案；
- 没有将本地匹配曲目描述为 AI 实时生成；
- 没有医学确诊、治愈率或替代医生的表述。

### 交付

- 演示固定案例可在联网和 Qwen 失效两种模式下完成；
- 有备用本地音频和录屏；
- 参赛版本有明确 commit/tag；
- README 或演示说明中记录启动方式、环境变量和降级模式；
- 五名成员均完成各自验收项，陈家智进行最终签收。
