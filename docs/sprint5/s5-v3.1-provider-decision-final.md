## 2. Provider Configuration Policy

Only deployment environment variables or the deployment secret manager may contain credentials. Repository files, frontend bundles, screenshots, CI logs, issue comments, and ordinary application logs must never contain keys or bearer tokens.

Approved configuration names:

- Qwen: `QWEN_BASE_URL`, `QWEN_API_KEY`, `QWEN_MODEL`
- Embedding: `EMBEDDING_PROVIDER`, `EMBEDDING_BASE_URL`, `EMBEDDING_API_KEY`, `EMBEDDING_MODEL`, `EMBEDDING_DIMENSION`
- Chroma: `CHROMA_PERSIST_DIRECTORY`, `CHROMA_COLLECTION`
- Music: `MUSIC_PROVIDER`, `MUSIC_PROVIDER_BASE_URL`, `MUSIC_PROVIDER_API_KEY`, `MUSIC_PROVIDER_MODEL`
- Backend Agent runtime: `HARMONYAI_REAL_AGENTS` (production deployment must set it explicitly to `true`)

Production defaults must not select mock mode. Missing required real-mode configuration must produce a readiness failure or explicit provider error.

## 3. Real / Mixed / Mock Policy

- **Real:** every provider-facing stage used by the request is backed by its approved provider and produces auditable provider metadata.
- **Mixed:** explicitly labelled run in which one or more stages use an approved deterministic fallback. It must identify each degraded stage.
- **Mock:** local development/test only, entered through an explicit development mechanism. It must never be enabled by stale browser storage or production defaults.
- A run with `hash-v1`, demo Chroma chunks, hard-coded diagnosis, simulated music completion, or a bundled demonstration asset is not Real.

## 4. Fallback Policy

| Failure | Required behavior |
| --- | --- |
| PaddleOCR unavailable/fails/returns unusable content | Return the frozen document failure outcome and allow re-upload or transfer to the no-document questionnaire path. Do not forward failed OCR as evidence. |
| Qwen Understanding fails or violates schema | Retry only within the bounded provider policy. Then use validated deterministic facts where sufficient; otherwise return degraded/abstain. Do not invent facts. |
| Embedding or Chroma fails | Agent2 may continue only if an approved deterministic rule path is sufficient and the result is labelled degraded; otherwise abstain. |
| Qwen Diagnosis fails or violates schema/rules | Reject invalid output. Use an approved deterministic result only when evidence and rules support it; otherwise abstain. |
| Music Provider fails | Use `matched_fallback` only when a reviewed playable asset matches the policy. Otherwise return explicit `NO_PLAYABLE_ASSET`/provider failure. |
| Audio materialization fails | Mark generation failed. Never expose a temporary provider URL as a permanent player asset. |

## 5. Required Real Smoke Evidence

The following remain mandatory before `REAL_VALIDATED`:

- [ ] PaddleOCR: JPG/PNG and supported multi-page input, including empty/low-confidence/failure routing.
- [ ] Qwen Understanding: one redacted structured-output success plus timeout, auth, rate-limit, invalid JSON, and schema-invalid cases.
- [ ] Embedding: real vector request, 1024-dimension validation, query/document distinction, and no `hash-v1` production index.
- [ ] Chroma: approved corpus ingestion, Top-K retrieval with source references, empty result, and corrupted/unavailable index behavior.
- [ ] Qwen Diagnosis: RAG-grounded structured result, schema validation, rule validation, insufficient evidence, and provider failure.
- [ ] MiniMax Music: select and record the exact model/version/endpoint, then verify real create success, playable asset, format/duration, provider failure, idempotency protection, and honest capability mapping.
- [ ] Audio Asset: provider payload downloaded/materialized into owned storage and served through authenticated player access.
