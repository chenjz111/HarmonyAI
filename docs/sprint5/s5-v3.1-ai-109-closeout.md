## Implemented

1. Added a V3.1 Embedding boundary with explicit `text-embedding-v4`, 1024
   dimensions, query/document input types, bounded retry, timeout/error mapping,
   and secret-free failures. The runtime resolver reads
   `DASHSCOPE_API_KEY` and `DASHSCOPE_WORKSPACE_ID`; the latter is propagated
   as a provider header without appearing in readiness output.
2. Added versioned Chroma ingestion and retrieval. Collection identity is bound
   to knowledge version, embedding version, dimension, and manifest checksum.
   Production ingestion rejects pending medical assets, non-approved chunks,
   stale versions, non-approved Embedding identities, and any manifest/chunk
   content whose recomputed checksum differs from its declared checksum.
3. Added deterministic Agent2 query construction and a Qwen-compatible adapter.
   The adapter performs one schema-repair attempt, validates approved syndrome,
   Fact, and knowledge-chunk references, validates evidence direction and
   medical-rule version, and maps provider errors safely. RAG-empty results
   are evidence-gated abstentions; RAG/provider/schema/rule failures are
   explicit failures; Qwen is not
   called without grounded successful retrieval.
   The syndrome allowlist is loaded from the configured Owner-approved medical
   rule asset only; its approved version, embedded checksum, configured
   checksum, review status, and corpus release are checked before the factory
   returns a provider. `V31_ALLOWED_SYNDROME_CODES` is rejected in Real mode.
4. Added deterministic Agent3 V3.1 `ToneProfile` and an internal
   `GenerationSpecV31` builder. Primary/secondary tone, BPM, instruments,
   ambience, duration and explanations come from a reviewed rule asset;
   UserGoal can only select one of the seven formal Agent3 rule rows and never
   enters Agent1, Agent2, FactEvidence or OrganEvidence. The asset schema
   requires all seven codes, rejects arbitrary keys, bounds BPM to 40--120 and
   duration to at most 300 seconds, and applies the deterministic
   `primary_over_secondary_fill_missing` merge policy. Goal rows are partial
   field overrides: primary wins an explicitly covered field, secondary fills
   only a primary omission, and explanations are merged per final field.
   Without an approved
   secondary-tone threshold, secondary tone remains null while the approved
   primary tone and music parameters remain ready with a safe optional-
   capability message. The Owner-approved deterministic asset is recorded at
   `knowledge/v3/music-generation-rules-v3.1.json` as
   `music-generation-rules-v3.1-r1`; the candidate Markdown remains its review
   provenance rather than a runtime input.
5. Added the Agent1 V3.1 boundary adapter. It accepts 1--3 current
   persistence-owned documents in saved order, requires complete per-document
   Relevance rows, passes only `VALID` sources downstream, preserves document
   provenance, and blocks `INSUFFICIENT`, stale, superseded, discarded,
   cross-user and cross-session inputs. Questionnaire `3.0.1` results map
   deterministically into confirmed normalized facts and can be fused with
   document facts or used alone.
6. Added and wired the V3.1 chain seam:
   `ConfirmedUserState -> Query Builder -> RAG -> Qwen -> Diagnosis ->
   ToneProfile -> GenerationSpec -> Five-Tone Read Model`. The formal
   `/api/v3/diagnoses` service reaches this seam in Real mode through an
   owner-scoped projection adapter and never copies UserGoal into the Agent2
   request. Successful, failed, and evidence-abstained provider attempts keep
   linked safe RAG/provider audit rows; only hashes and approved references
   are persisted, never keys, full prompts, raw user text, or embeddings.
7. Added the Real-mode factory boundary. It requires complete DashScope,
   Chroma, Qwen, and corpus manifest/chunk configuration, validates and ingests
   the configured corpus before retrieval, and maps missing or invalid assets
   to readiness failures without selecting Mock or demo data.
   Agent3 additionally requires the separately approved
   `music_generation_rules_v3.1` asset, its explicit version, and its canonical
   checksum; the five-tone safe-expression asset is not used for music
   parameters.
8. Added a PR #114-bound candidate corpus package containing 13 exact source
   registry scope rows, per-chunk/package checksums, and a separate candidate
   ingestion manifest. The package is explicitly pending medical content review
   and is rejected by the production loader; it is not presented as approved
   medical corpus content.
9. Added explicit candidate promotion validation, a production Chroma index
   builder, deterministic secret-free index receipts, persisted-index reuse by
   manifest/chunk checksum, and an Owner-only real-provider smoke command.
   The builder sends document embeddings only after production approval and
   verifies the final Chroma count before writing a receipt.
10. Added the Owner-approved `medical_rules_v3.1` release at
    `knowledge/v3/medical-rules-v3.1.json`. The release is checksum-gated and
    exposes only `syd_001`--`syd_008` as Agent2 codes; English values are
    semantic aliases only. The candidate ingestion manifest records the
    intentional empty `claim_codes`/`organ_codes` semantics and the production
    manifest schema requires the same field when all approved chunks are
    intentionally unlabelled.
