## Implemented

1. Added a V3.1 Embedding boundary with explicit `text-embedding-v4`, 1024
   dimensions, query/document input types, bounded retry, timeout/error mapping,
   and secret-free failures.
2. Added versioned Chroma ingestion and retrieval. Collection identity is bound
   to knowledge version, embedding version, dimension, and manifest checksum.
   Production ingestion rejects pending medical assets, non-approved chunks,
   stale versions, and non-approved Embedding identities.
3. Added deterministic Agent2 query construction and a Qwen-compatible adapter.
   The adapter performs one schema-repair attempt, validates approved syndrome,
   Fact, and knowledge-chunk references, and maps provider errors safely.
   RAG-empty results abstain; RAG-unavailable results are degraded; Qwen is not
   called without grounded successful retrieval.
4. Added deterministic Agent3 V3.1 `ToneProfile` and an internal
   `GenerationSpecV31` builder. Primary/secondary tone, BPM, instruments,
   ambience, duration and explanations come from a reviewed rule asset;
   UserGoal can only select an explicitly named Agent3 rule row and never
   enters Agent1, Agent2, FactEvidence or OrganEvidence. Without an approved
   secondary-tone threshold, secondary tone remains null and the public read
   model is `not_ready` with a safe blocker message.
5. Added the Agent1 V3.1 boundary adapter. It accepts 1--3 current
   persistence-owned documents in saved order, requires complete per-document
   Relevance rows, passes only `VALID` sources downstream, preserves document
   provenance, and blocks `INSUFFICIENT`, stale, superseded, discarded,
   cross-user and cross-session inputs. Questionnaire `3.0.1` results map
   deterministically into confirmed normalized facts and can be fused with
   document facts or used alone.
6. Added the provider-neutral V3.1 chain seam:
   `ConfirmedUserState -> Query Builder -> RAG -> Qwen -> Diagnosis ->
   ToneProfile -> GenerationSpec -> Five-Tone Read Model`. The seam requires a
   current, confirmed state and never copies UserGoal into the Agent2 request.

## Current capability label

`NOT_REAL_VALIDATED` / `BLOCKED_BY_MEDICAL_ASSET`

This PR completes the AI foundation, explicit degraded gates, and provider
chain seam. It must not be described as `REAL_RAG_QWEN` or as a complete
Agent2 production integration.

Real RAG + Qwen is not enabled because the approved Issue #108 corpus is still
pending production release and does not yet provide the complete chunk payload
and ingestion manifest metadata required by the gate. In particular, the
production release still needs approved chunk text/display summaries/sections,
claim and organ codes, embedding provider/model/version, distance metric,
minimum score, chunk count, and manifest checksum. The approved syndrome
whitelist and its medical-rule release are also not present in this baseline.

The current code therefore supports injected test doubles and explicit
degraded/abstained behavior only. Production configuration requires real
Embedding, Chroma, Qwen, and an existing production corpus manifest; the
factory rejects incomplete configuration and never calls the legacy demo
loader. The legacy V3.0 `get_knowledge_store()` behavior remains unchanged
for compatibility.
