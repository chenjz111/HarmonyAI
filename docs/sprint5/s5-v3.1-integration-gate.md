# HarmonyAI Sprint 5 V3.1 Integration Gate

> Status: **PROVISIONAL — FINAL FREEZE REVIEW; DO NOT MERGE UNTIL OWNER FREEZE**

## 1. Purpose

This gate prevents independently developed V3.1 work from creating incompatible flow, schema, persistence, and provider assumptions. Feature branches and Draft PRs may be used for review; integration remains closed until the contract is confirmed and every applicable gate has evidence.

Related coordination: Sprint 5 task tracker issue #95 and Owner baseline issue #96, where available.

## 2. Work Allowed Before Freeze

- Read-only audits, prototypes, decision records and Draft PRs.
- Implementation behind an isolated feature flag when it does not alter the authoritative integration behavior.
- Tests that describe provisional behavior and are clearly marked against the draft version.

Not allowed before freeze:

- Merging a V3.1 flow/schema change into integration.
- Calling the current draft `FROZEN`, `FINAL`, or `OWNER_APPROVED_FINAL`.
- Destructive deletion of Sprint 4/V3 compatibility data or routes.
- Treating mock Provider output as real production evidence.

## 4. Required Merge Evidence

Every V3.1 PR must provide:

- Frozen contract section(s) implemented.
- Base/head commits and changed-file scope.
- Targeted test command and unabridged result summary.
- Contract/schema compatibility result.
- Migration upgrade/rollback evidence when persistence changes.
- Real versus mock/degraded execution evidence for Provider-facing code.
- H5 and Android evidence for user-flow changes.
- Confirmation that unrelated Sprint 4/V3 behavior was not silently removed.

## 5. Stop Conditions

Stop integration and return the PR to Draft when any of the following occurs:

- Implementation relies on an unresolved contract decision.
- Two PRs introduce competing schema/table/route ownership.
- Frontend derives authority from stale local state instead of the server session.
- A failed OCR/RAG/LLM/music call is reported as real success.
- UserGoal or feedback overwrites medical/state evidence.
- A schema or applied migration is rewritten instead of versioned safely.
- Tests pass only against self-authored fixtures that bypass the real boundary under review.
