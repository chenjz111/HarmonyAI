# V3.1 RAG Gold threshold analysis

## Input and evaluation boundary

The Owner-exported matrix was evaluated without changing the Gold labels,
chunk text or medical mappings:

- input: `harmony-rag-gold-similarity-matrix.json`
- matrix checksum: `sha256:e6f34207f90345fe104eafa93006b694cb5ccbea214cbd17e0ab136458b0c30a`
- rows: 221 (`17 queries x 13 chunks`)
- labels: 18 relevant, 9 boundary, 194 irrelevant
- embedding: `text-embedding-v4`, dimension 1024, cosine similarity

The evaluation mirrors the current `RagStore` behavior: sort by similarity,
take the requested Top-K, then remove rows below `minimum_score`. The reported
thresholds below are cosine-space thresholds from the Owner matrix.

- Top-1 hit: the eligible Top-1 row is labeled `relevant`.
- P@K: relevant returned rows divided by returned rows.
- R@K: relevant returned rows divided by the query's relevant Gold rows.
- `NA` precision means no row was returned; `NA` recall means the query has no
  relevant Gold row. These values are excluded from the corresponding macro
  average.
- Gold no-answer queries are `gq_14`, `gq_15`, and `gq_17`. `abstain=yes`
  means the threshold produced no eligible Top-5 row; a non-empty irrelevant
  result is reported as a false hit, not as a successful answer.

The runtime manifest currently describes `normalized_similarity`, while the
Owner matrix contains raw cosine similarity. Chroma cosine distance is
converted by the current store to `1 / (1 + distance)`. Assuming Chroma's
cosine distance is `1 - cosine`, the equivalent runtime thresholds are:

| Matrix cosine threshold | Runtime `minimum_score` equivalent |
|---:|---:|
| 0.55 | 0.689655 |
| 0.60 | 0.714286 |
| 0.65 | 0.740741 |

This conversion must be resolved before writing the final approved manifest;
the raw cosine values must not be copied into a normalized-similarity field.

## Boundary and no-answer cases

- `gq_14`: no relevant Gold chunk. `src_10` scores 0.6184 and is returned
  incorrectly at 0.55 and 0.60; it is filtered at 0.65.
- `gq_15`: no relevant Gold chunk and no eligible result at all three
  thresholds; it abstains at all three thresholds.
- `gq_17`: no relevant Gold chunk. `src_11` scores 0.6343 and is returned
  incorrectly at 0.55 and 0.60; it is filtered at 0.65.

Therefore, threshold-only abstention is reliable for all three gold no-answer
queries only at 0.65. At 0.55 and 0.60, `gq_14` and `gq_17` are non-empty
irrelevant false hits and must not be described as successful retrieval.

## gq_01 -> src_12 analysis

The Gold query is “为什么容易烦躁易怒被认为与肝有关？”. `src_01` directly
contains the anger/liver correspondence and scores 0.5574. `src_12` is labeled
relevant because it contains the supporting statement “情志调畅赖肝”, but the
chunk is a mixed summary of “喘证病机；痰饮；情志调畅赖肝” and does not
directly express “烦躁易怒” or “怒为肝志”. Its 0.4669 score is therefore a
weak/indirect semantic match, not a reason to change the Gold label.

The operational impact is clear: `src_12` is below all three candidate
thresholds. At 0.55, `src_01` is retained but an irrelevant `src_11` at 0.5719
outranks it, producing P@5=0.500 and R@5=0.500 for `gq_01`. At 0.60 and 0.65,
both relevant rows are filtered and `gq_01` abstains. Lowering to 0.55 recovers
only one of the two relevant rows while adding 30 irrelevant hits overall, so
this is a corpus/query coverage boundary rather than a safe reason to lower
the threshold.

## Owner decision proposal

Recommended: **0.65 cosine** (equivalent to approximately **0.740741** under
the current normalized-similarity runtime conversion).

- It has the same relevant recall as 0.60: 15/18.
- It reduces irrelevant false hits from 11/194 to 3/194.
- It makes all three no-answer queries threshold-empty.
- It sacrifices one boundary row compared with 0.60: 4/9 versus 5/9.

Fallback for a recall/boundary-priority review: **0.60 cosine** (runtime
equivalent approximately **0.714286**). It retains one more boundary row but
allows false hits for `gq_14` and `gq_17`; it should not be treated as the
safety-conservative option without an additional domain/no-answer gate.

The Owner must choose the final value. Until that choice is recorded, no
approved corpus or manifest is generated.
