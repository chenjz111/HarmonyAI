# Guest 音乐库：Android USB 非生产验收

状态：准备中；本轮无设备，以下全部新验收为 NOT RUN。采用现有 HBuilderX 标准基座和精确 USB 例外；不是独立 APK 或正式开关验收。原始资料、分享和长期学习继续关闭，不能调用付费 Provider。

## 开始前：必须先由工程侧完成

1. 准备仅监听 `127.0.0.1:8000` 的隔离 FastAPI、隔离 SQLite 和媒体目录；确认登录、会话、音乐库、反馈路由使用真实鉴权，注册账号和付费生成关闭。必须核查运行的源码提交、数据库与媒体路径，不能误连生产或已有用户库。确保测试 JWT 签名密钥跨后端重启保持稳定并安全保存；不要记录密钥或 token。
2. 准备同一测试游客已有的合法测试音乐，至少包含一首有资产但尚未播放的音乐。记录素材来源、文件类型、真实时长和 checksum；不能把合成音乐说成真实生成。已有历史音乐若须继续使用，先核对它属于该隔离库和同一游客；不得重置或覆盖原有身份。
3. **当前尚未就绪**：早期 `local-guest-backend-20261026` 只开放基础身份/会话，不能完成音乐库验收；另一套 `serve_real.py` 配置真实付费 Provider，不能直接用于本轮。需要先准备、核验并记录无需 Provider 的音乐库测试后端和合法资产，再按下列步骤执行。不得因 `/health` 正常就认定前提满足。
4. 在本机隔离 frontend 的开发配置确认 `VITE_S7_USB_GUEST_DEBUG=1`、`VITE_S7_USB_LIBRARY_LIVE=1`、`VITE_API_BASE_URL=http://127.0.0.1:8000`。只在 Android development 生效；正式构建默认关闭，勿复制到生产配置。标准基座需要支持该 loopback HTTP；实际通过后才能确认。

连接设备后可在电脑 PowerShell 执行（仅当前已授权设备，若出现多个设备先明确选择，不粘贴设备序列号到聊天）：

```powershell
$s7Adb = 'C:/Users/ASUS/HBuilderX/HBuilderX/plugins/launcher-tools/tools/adbs/adb.exe'
& $s7Adb devices
& $s7Adb reverse --list
& $s7Adb reverse tcp:8000 tcp:8000
Invoke-RestMethod 'http://127.0.0.1:8000/health'
```

电脑健康检查只能证明电脑能访问服务；手机侧如果已自带 `curl`，可用 `& $s7Adb shell curl http://127.0.0.1:8000/health` 验证映射，否则通过标准基座真实请求验证，不安装诊断软件。

## 操作与记录

| 步骤 | 用户操作 | 预期 | 失败时记录与关闭的阻塞 |
|---|---|---|---|
|1 连接|数据线连接并允许 USB 调试；电脑用已有 HBuilderX ADB 查看 `devices`、`reverse --list`，必要时对该已授权设备设置 `reverse tcp:8000 tcp:8000`。|设备状态为 device，映射到电脑 8000。|只记录设备状态和映射，不发序列号；解决设备/USB 通路。|
|2 启动|工程侧先验证独立后端、合成数据与上述安全前置条件；HBuilderX 打开此隔离 frontend，运行到 Android App 标准基座。|首页使用原合法测试游客，无强制注册；禁止清除 App 数据。|记录健康响应、非敏感控制台错误和构建标识；解决入口/连接阻塞。|
|3 历史|我的→历史音乐，查看已准备的未播放音乐。|显示真实资产和合理标题，未播放不产生播放事件；不点生成。|记录页面提示、请求路径和状态码（不含授权头）；解决未播放资产进入历史。|
|4 收藏和改名|打开歌曲、收藏；返回历史及收藏，改一个无敏感信息的名字，切换列表查看；再取消收藏。|两列表及同一 Player 状态一致，收藏不强制命名；不生成新音乐。|记录操作顺序与错误码；解决跨页面状态同步。|
|5 播放与反馈|点击播放、暂停、Seek；实际播放后进入反馈，选项提交后查看历史、删除；从反馈返回 Player 后再次播放。|仅真实 onPlay 产生关联事件；反馈属于当前歌曲/播放；返回后可播放。|记录时间、可见提示、无敏感内容的状态码；解决播放证明、逐曲反馈及返回播放。|
|6 Clear|创建测试反馈后，使用“清除所有音乐的学习证据资格”，再次查看未单独删除的历史反馈。|历史仍可见、学习始终 OFF；单独删除的记录不复活。|记录操作与提示；解决 Clear 用户语义。避免使用真实敏感反馈。|
|7 重启|暂停音频，关闭并从最近任务划掉基座，再重开同一项目；不要清数据或新建游客。|原游客仍能看到原音乐及其状态。|记录是否提示身份失效、后端是否重启；解决 App 进程重启恢复。密钥变更导致失效不是通过。|
|8 网络/身份|操作前断开 USB 或停止隔离服务，查看错误；恢复后重试。过期凭据不得自动创建新游客。第二游客仅使用明确隔离的合成身份。|错误可理解、不显示另一游客数据；回网可恢复，失效需明确处理。|记录非敏感时间线与状态码；解决断网、401 和跨用户隔离。不要擅自替换或清除原游客。|

**当前已知阻塞：** 同一进程内关闭反馈页后，同一播放事件的未知提交现在会安全阻止新键；但进程被回收或重启后无法恢复未知状态，仍可能重复提交，不得把该场景标为通过。保持同页并原请求重试；跨进程恢复须先修复和验证。页面方法的 ASGI 成功、WAV MIME 与媒体字节一致不证明 Android 解码、音频焦点或实际网络中断通过。
